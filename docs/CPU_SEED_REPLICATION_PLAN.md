# CPU 新种子验证：仅末步监督下，两步与四步的收益能否重复

执行前方案日期：2026-10-11。新种子及筛选规则在读取本轮任何训练结果前确定。本轮是已观察 tune 开发集上的训练随机性复核，延续上一轮条件，尚不扩大病例。

## 问题与固定设计

问题：上一轮仅末步监督中，四步模型的 Brier 在三个种子上均优于独立两步模型。这个方向在五个新种子上能否重复？

- 新训练种子固定为 **53、71、89、107、131**；此前 17、29、43 不计入主要判断。
- 每个新种子分别从头训练两步和四步 SJ 模型，共 **10 次拟合**，只在最终输出联合监督分类与分割。中间隐藏状态仍通过完整循环接收梯度。
- 与上一轮完全相同的 128 个训练 Case（87 良性、41 恶性、227 张图），159 个 tune Case（108 良性、51 恶性、281 张图）。固定选择种子 20261004。
- 同一种子的两种深度使用相同初始参数、训练病例顺序和视图抽样。每轮每 Case 抽一张图；评估先平均各视图概率，再计算 Case 指标。
- 50 epoch、batch size 2、3,200 次更新、学习率 0.0003、AdamW weight decay 0.01；联合损失、梯度裁剪及数据预处理与上一轮相同。
- 共享 Transformer 和分类/mask 头共 714,530 个可训练参数；DeiT-Tiny 编码器的 5,717,416 个参数冻结。无增强，复用指纹核验过的特征缓存；不复用已训练模型权重。
- 每五个 epoch 记录开发曲线，统一采用第 50 epoch，不挑更好的种子、epoch 或学习率。
- 两路 CPU worker，每路两个 PyTorch 线程；准备先完成，再分配互不重叠的五次拟合。失败目录不自动覆盖重训。

两种深度的更新数和病例接触次数相同，四步允许额外循环计算；这不是等 FLOPs 比较。训练代码、模型、数据选择、编码器权重、manifest 和初始参数指纹锁定，与上一轮训练代码保持一致。

## 主分析及预先确定的推进规则

对每个新种子：**G = Brier（独立训练两步的最终输出）− Brier（独立训练四步的最终输出）**。G 正表示四步概率预测误差较低。

主要报告五个新种子的逐项结果、平均 G、样本标准差和配对 Case bootstrap 区间（2,000 次，bootstrap 种子 17）。先在同一 Case 内平均各拟合种子的效应，再重采样 159 个 Case，避免将 5×159 个预测当作独立患者。区间条件于五个已训练模型，不包含训练种子总体的不确定性。

同时满足以下三项，才建议进入另一个、单独锁定方案的 256 Case CPU 实验：

1. **至少 4/5 个新种子 G > 0。**
2. **依次移除任意一个种子，剩余四个种子的平均 G 都 > 0。** 这是将“不靠单个异常种子撑起均值”具体化。
3. **平均 NLL₄−NLL₂ ≤ 0。** 作为概率质量保护条件，避免只根据 Brier 决定推进；同时公开每个种子的 NLL 变化。NLL 保持现有 epsilon=1e−15 裁剪，极端概率饱和会影响它。

采用未四舍五入的指标计算条件。前两项检查深度收益的训练随机性一致性，第三项单独检查概率损失。AUROC、Dice 和高置信错误也报告，但不事后增减硬门槛。

这些是**资源筛选规则**，不是显著性检验、临床有效性、概率校准或 GPU 投入的证明。通过也不自动启动 256 Case 实验。若未通过，报告具体失败条件，并优先诊断优化/过拟合；不能用旧三个正向种子掩盖新结果。

## 次分析与误差检查

- AUROC、NLL、Case 平均 Dice，固定 0.5 阈值的敏感度/特异度。
- 同一 Case 两步/四步之间纠正和恶化的分类数量；概率平方误差的改善和恶化另行计算，不混为一件事。
- 错误且预测概率 ≤0.05 或 ≥0.95 的 Case 数量、精确 0/1 概率、每个 Case 的误差贡献，以及移除最大正向贡献 Case 后的描述性变化。
- 最终训练/开发误差差距、完整学习曲线。中间读出未直接监督，只作诊断观察。
- 旧三个种子可与新五个合成 **八个种子的次要描述性汇总**；主要表、图和推进规则只用新五个。

病例/视图/标签集合、50 epoch、3,200 updates、监督位置、初始化和源代码指纹全部复核；开发指标由本地逐图记录重新计算，不能只信 summary。原始影像、逐病例预测、缓存与权重不上传，公开代码、配置、汇总和图。

## 数据用途与限制

仅 train/tune 的图像和预测参与本轮。cal/test 继续封存，不用于校准、模型选择或本轮报告。Case 与患者身份对应尚未核实，开发集也已反复观察；更多训练种子不会增加独立评估病例，不能将本轮称为独立临床验证。

如果建议扩充病例，另行明确 128/256 的数据选择和预算。本计划不执行扩充；固定 3,200 updates 可检验相同优化预算下更多不同病例的作用，而固定 50 epoch 会同时增加优化次数，两者回答不同问题。
